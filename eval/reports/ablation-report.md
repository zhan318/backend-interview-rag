## 一、实验目的

把「最终效果」拆开，回答每层优化的独立贡献：

1. dense 单路在 top-3 / top-5 / top-20 三种口径下分别多准（口径不同不可直接比较）
2. RRF 融合相比最好的单路，净增益多少
3. Cross-Encoder 精排相比 RRF，净增益多少、延迟代价多少
4. 阈值 0.2 是保护（挡住无关文档）还是误杀（丢掉相关文档）

## 七、结论

1. **精排净增益 +9.5pp**（RRF 13/21 → 精排 15/21），代价是单条延迟 15ms → 6394ms（419×）。CPU 环境下精排是检索链路的主要成本，是否保留取决于延迟预算。

2. **阈值不影响精度**（有阈值 15/21 vs 无阈值 15/21），但它决定库外问题是否被拦下：not_in_kb 越界检出 0/4 vs 4/4。它的定位是防幻觉，不是提精度。

3. **融合截断存在召回风险**：RRF@20 = 13/21，低于 BM25 单路@20 = 15/21。原因是融合后截断到 recall_n，两路合并去重后的尾部文档被挤出；当前靠精排从候选中补回，换语料或换 query 分布时可能暴露。
